# BHS 스키아카데미 반편성 사이트 — 설계 문서

날짜: 2026-08-25

## 배경 및 목표

쿠폰제 유소년 방학 프로그램(화·수·목, 오전/오후 레슨)을 운영하며, 전날 또는
당일에 선생님과 아이들을 반에 배정한다. 기존에는 손글씨로 반편성표를 작성해
카톡으로 학부모에게 개별 전송하고 쿠폰 차감도 수기로 계산했다.

이 사이트의 목표:

- 학부모는 링크 하나로 당일/익일 반편성표를 실시간 확인
- 관리자는 웹에서 반편성을 하고, 쿠폰은 배정과 동시에 자동 차감
- 카톡 개별 전송과 수기 쿠폰 계산 제거

## 사용자와 접근

- **학부모**: 로그인 없음. 공개 링크(`/`)를 열면 전체 반편성표가 보인다.
  쿠폰 정보는 학부모 페이지에 표시하지 않는다 (문의 시 관리자가 확인해 안내).
- **관리자**: `/admin`에서 공용 비밀번호 하나로 입장. 비밀번호는 환경변수로
  관리하며 세션 쿠키로 로그인 상태를 유지한다.

## 화면 구성

### 학부모 페이지 (`/`)

- 상단 날짜 선택: 오늘/내일 탭 (배정이 전날 올라오는 운영 방식 반영)
- 오전 / 오후 섹션으로 나누어 반 카드 나열
- 반 카드: 담당 선생님 이름 + 배정된 아이들 이름 목록
- 배정이 없으면 "아직 반편성 전입니다" 안내
- 30초 간격 자동 갱신(폴링)
- 모바일(카톡 인앱 브라우저) 우선 세로형 레이아웃

### 관리자 페이지 (`/admin`)

- **반편성**: 날짜 + 오전/오후 선택 → 반 생성(선생님 지정) → 아이 명단에서
  탭하여 반에 배치. 배치 즉시 쿠폰 1회 자동 차감, 배치 취소 시 자동 복구.
- **아이 관리**: 아이 등록(이름, 메모), 쿠폰 충전(+N회), 남은 횟수 확인
- **선생님 관리**: 이름 등록/삭제(비활성화)
- 쿠폰 잔여 0인 아이 배치 시 경고 표시(빨간색)하되 배치는 허용 — 현장 유연성 유지

## 데이터 모델 (Postgres + Prisma)

| 테이블 | 내용 |
|---|---|
| `teachers` | 선생님: 이름, 활성 여부 |
| `students` | 아이: 이름, 메모(학년/레벨 등) |
| `coupon_events` | 쿠폰 이력: 아이, 증감량(+충전/-차감/+복구), 사유, 시각 |
| `classes` | 반: 날짜, 시간대(오전/오후), 담당 선생님 |
| `class_students` | 배정: 반 ↔ 아이 |

- 남은 쿠폰 = `coupon_events` 증감량 합계. 숫자 하나가 아닌 이력을 남겨
  "왜 N회 남았는지" 관리자가 추적 가능.
- **중복 배치 제약 없음**: 같은 아이가 같은 날짜·같은 시간대에 여러 반에
  들어갈 수 있다(연달아 수업 받는 경우 존재). 배치될 때마다 1회씩 차감.

## 핵심 흐름

1. 아이 배치: `class_students` 추가 + `coupon_events` -1 기록을 **한
   트랜잭션**으로 처리 (배정과 차감이 어긋나지 않음)
2. 배치 취소: 배정 삭제 + `coupon_events` +1 복구를 한 트랜잭션으로 처리
3. 학부모 조회 API: 날짜별 `classes` + 선생님 이름 + 배정된 아이 이름만
   반환. 쿠폰 데이터는 응답에 포함하지 않는다.

## 인증 및 보안

- 관리자 비밀번호는 환경변수(`ADMIN_PASSWORD`)로 설정
- 로그인 성공 시 서명된 세션 쿠키 발급, 이후 관리자 API는 세션 검증 필수
- 학부모 조회 API만 공개, 나머지(생성/배치/충전 등)는 전부 인증 필요

## 에러 처리

- 배치+차감 트랜잭션으로 데이터 어긋남 방지
- 관리자 화면: 요청 실패 시 실패 표시 + 재시도 버튼
- 학부모 화면: 배정 없음 → 안내 문구

## 기술 스택 및 배포

- Next.js (App Router) + Prisma + Postgres
- 배포: Railway (Pro 보유) — 앱 서비스 + Postgres 서비스
- 실시간: 30초 폴링 (규모상 웹소켓 불필요)
- 알림: 별도 알림 기능 없음. 사이트 확인으로 정착시키는 방침.

## 테스트

- 자동 테스트: 쿠폰 합산(충전/차감/복구), 배치/취소 트랜잭션 로직
- 수동 검증: 브라우저에서 반 생성 → 아이 배치 → 학부모 페이지 확인 →
  배치 취소 → 쿠폰 복구까지 전체 흐름
